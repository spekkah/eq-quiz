# Report: Программа тренировки слуха для EQ-тренажёра

## 1. Цель тренажёра

Основная задача — научить пользователя уверенно распознавать изменения в спектре, постепенно уменьшая заметность EQ-воздействия.

Тренировка должна быть адаптивной: приложение не просто выдаёт одинаковые вопросы, а отслеживает слабые места пользователя и увеличивает нагрузку именно там.

---

## 2. Базовая структура тренировки

Рекомендуемая схема:

1. **Диагностика**

   * Пользователь проходит короткий общий тест по доступному диапазону частот.
   * Например, 10–20 попыток.
   * Для каждой попытки сохраняется:

     * исходная частота;
     * выбранная пользователем частота;
     * правильность ответа;
     * gain;
     * Q;
     * диапазон;
     * тип аудиоматериала.

2. **Поиск слабых зон**

   * Для каждой частоты рассчитывается текущая успешность.
   * Определяются частоты, на которых пользователь ошибается чаще всего.
   * Важно учитывать не только общий процент правильных ответов, но и то, **с чем пользователь путает конкретную частоту**.

3. **Локальная тренировка**

   * После диагностики приложение концентрируется на самой слабой зоне.
   * Например, если слабое место — **250 Hz**, тренировочный набор может состоять из:

     * 125 Hz;
     * 250 Hz;
     * 500 Hz.
   * Таким образом пользователь тренирует именно различение соседних спектральных областей, а не просто запоминание конкретной кнопки.

4. **Повторная диагностика**

   * После локального блока снова запускается небольшой общий тест.
   * Это позволяет проверить, действительно ли навык улучшился, а не только способность решать конкретный тренировочный паттерн.

---

## 3. Статистика и трекинг

### Не использовать только простое среднее за всю историю

Например:

> Пользователь раньше попадал в 10% случаев, а сейчас в 99%.

Среднее за всю историю будет долго оставаться низким и плохо отражать текущий навык.

Поэтому лучше использовать **скользящее окно** или **экспоненциальное сглаживание**.

### Вариант MVP: последние 20 попыток

Для каждой частоты хранить последние 20 ответов.

Пример:

```text
250 Hz
Последние 20: 18 правильных
Accuracy = 90%
```

После каждой новой попытки самый старый результат удаляется.

Плюс такого подхода — статистика быстро реагирует на улучшение или ухудшение пользователя.

### Более продвинутый вариант: EWMA

Можно использовать экспоненциально взвешенную оценку:

```text
score_new = α × result + (1 - α) × score_old
```

Где:

* `result = 1` — правильный ответ;
* `result = 0` — неправильный;
* `α` определяет, насколько сильно влияют последние попытки.

Это позволит не хранить большую историю для расчёта текущего уровня навыка.

---

## 4. Статистика должна быть привязана не только к частоте

Не стоит хранить просто:

```text
250 Hz → 82%
```

Лучше считать навык в контексте сложности:

```text
250 Hz
+15 dB → 98%
+12 dB → 94%
+9 dB  → 87%
+6 dB  → 71%
+3 dB  → 48%
```

Так становится понятно, какой уровень воздействия пользователь действительно способен обнаруживать.

Внутренний профиль может выглядеть примерно так:

```text
frequency × gain × Q × material
```

При этом для MVP необязательно сразу использовать все параметры независимо. Достаточно начать с:

```text
frequency × gain
```

а Q и тип материала подключить позже.

---

## 5. Как определять слабую частоту

Нужно смотреть не только на accuracy.

Например:

```text
125 Hz → 90%
250 Hz → 52%
500 Hz → 64%
1 kHz  → 91%
```

Очевидный кандидат для локальной тренировки — 250 Hz.

Но ещё полезнее хранить **ошибочные ответы**:

```text
Правильный: 250 Hz
Ответы:
500 Hz × 8
125 Hz × 3
1 kHz × 1
```

Это говорит о характере ошибки.

В данном случае пользователь, вероятно, плохо различает 250 и 500 Hz.

Это позволяет строить тренировку вокруг **различения соседних частот**, а не просто чаще показывать 250 Hz.

---

## 6. Локальный тренировочный пул

При слабой частоте желательно тренировать её вместе с соседями.

Для октавных частот:

```text
125 Hz
250 Hz  ← слабая
500 Hz
```

Если слабая частота 1 kHz:

```text
500 Hz
1 kHz   ← слабая
2 kHz
```

Это особенно полезно для обучения восприятию относительного спектрального баланса.

При этом не стоит полностью исключать остальные частоты.

Рекомендуемая логика:

```text
70–80% вопросов → слабая зона
20–30% вопросов → случайные частоты общего диапазона
```

Это уменьшает эффект запоминания локального паттерна.

---

## 7. Прогрессия gain

Идея с постепенным уменьшением gain хорошая.

Например:

```text
+15 dB
↓
+12 dB
↓
+9 dB
↓
+6 dB
↓
+3 dB
↓
0 dB
```

Но переход лучше делать не после одного успешного результата.

Например, уровень считается освоенным, если пользователь показывает:

```text
≥ 90–95% accuracy
```

на достаточном количестве попыток.

Практически полезнее использовать одновременно:

* минимальное количество попыток;
* требуемую точность;
* стабильность результата.

Например:

```text
Минимум 15 попыток
Accuracy ≥ 90%
```

Тогда пользователь не перейдёт дальше просто из-за случайной серии удачных ответов.

Для более строгого режима можно использовать 95%.

99% может оказаться слишком жёстким критерием и приводить к чрезмерному количеству повторений.

---

## 8. Текущие уровни сложности

### Easy

Текущий прототип:

* октавные частоты;
* примерно +12 dB;
* широкий EQ;
* Q ≈ 1–1.4.

Это хороший уровень для первичного обучения.

### Medium

Текущий прототип:

* третьоктавные частоты;
* примерно +9 dB;
* более узкая полоса;
* Q ≈ 4.

Здесь пользователь уже должен различать более локальные изменения спектра.

### Hard

Текущий прототип:

* случайная частота;
* случайный Q;
* около +6 dB;
* более высокая вариативность.

Это уже хороший кандидат на продвинутый режим, поскольку пользователь не может заранее знать точную частоту и ширину воздействия.

---

## 9. Важная архитектурная идея: сложности как независимые параметры

В перспективе лучше не привязывать всё к жёстким уровням Easy / Medium / Hard.

Вместо этого у тренажёра может быть несколько независимых осей сложности:

```text
Frequency resolution
Gain
Q
Frequency range
Material
```

Например:

```text
Resolution: octave
Gain: +12 dB
Q: 1.4
Material: pink noise
```

постепенно превращается в:

```text
Resolution: 1/3 octave
Gain: +6 dB
Q: 4
Material: music
```

Адаптивный алгоритм сможет менять только тот параметр, который действительно необходимо усложнить.

---

## 10. Frequency Range

Ручной выбор диапазона имеет смысл оставить.

Например:

```text
250 Hz – 1 kHz
```

или

```text
2 kHz – 20 kHz
```

Это может использоваться как:

* отдельная тренировка;
* подготовка к конкретной задаче;
* режим для пользователей, которые хотят прокачать определённую область.

При этом можно иметь отдельный **Adaptive Mode**, где диапазон автоматически выбирается на основе статистики пользователя.

---

## 11. Аудиоматериал

Для обучения полезно разделить этапы по сложности материала.

### Этап 1 — Pink Noise

Плюсы:

* стабильный и предсказуемый спектральный материал;
* изменения EQ легче контролировать;
* меньше отвлекающих факторов.

Это хороший материал для обучения фундаментальному распознаванию частот.

### Этап 2 — простые музыкальные источники

Например:

* отдельный инструмент;
* простой loop;
* минимальный музыкальный фрагмент.

Это повышает сложность, потому что пользователь начинает учитывать реальный тембральный контекст.

### Этап 3 — полноценный музыкальный материал

Здесь уже тренируется навык, максимально близкий к реальной работе с миксом.

Таким образом можно получить:

```text
Pink Noise
↓
Simple Audio
↓
Music / Mix
```

А не использовать один материал на всех этапах.

---

## 12. Рекомендуемый MVP-алгоритм

Для первой рабочей версии можно сделать относительно простой цикл:

```text
1. Пользователь выбирает Frequency Range.

2. Диагностический раунд:
   15–20 вопросов.

3. Для каждой частоты рассчитывается:
   - accuracy;
   - количество попыток;
   - самые частые неправильные ответы.

4. Выбирается слабая частота.

5. Создаётся локальный пул:
   слабая частота + ближайшие соседи.

6. Запускается 10–20 тренировочных вопросов:
   70–80% слабая зона,
   20–30% random.

7. Если accuracy стабильно ≥ 90–95%:
   уменьшить gain.

8. Повторять:
   +15 → +12 → +9 → +6 → +3 dB.

9. После прохождения нескольких уровней:
   провести повторную глобальную диагностику.

10. Сравнить профиль с предыдущей диагностикой.
```

---

## 13. Что показывать пользователю

Внутри приложения можно хранить намного больше данных, чем показывать пользователю.

Пользователю достаточно простой информации:

```text
250 Hz
+12 dB — освоено
+9 dB  — освоено
+6 dB  — в процессе

Accuracy: 91%
```

А внутренне хранить:

```text
frequency
gain
Q
correct
incorrect
answered_frequency
timestamp
material
```

Это позволит позже значительно усложнить адаптивный алгоритм без изменения структуры данных.

---

## 14. Долгосрочное направление

Вместо фиксированной системы:

```text
Easy
Medium
Hard
```

можно постепенно перейти к **профилю слухового навыка**.

Например:

```text
Low frequencies       84%
Mid frequencies       61%
High frequencies      93%

Broad EQ              91%
Narrow EQ             68%

+12 dB                96%
+9 dB                 88%
+6 dB                 63%
+3 dB                 31%
```

Тогда тренажёр сам определяет, что дать пользователю дальше.

В итоге приложение становится не набором уровней, а системой, которая постоянно отвечает на вопрос:

> «Что именно этому пользователю сейчас сложнее всего услышать?»

И именно это тренирует.

## 15. Рекомендация для текущего прототипа

На данном этапе нет необходимости сразу строить сложную систему машинного обучения или полноценный skill-rating.

Оптимальный MVP:

**октавные частоты → 15–20 диагностических вопросов → последние 20 попыток для статистики → определение слабой частоты → тренировка слабой частоты + соседей → постепенное снижение gain → повторная диагностика.**

Это уже даст хорошую основу для проверки самой идеи адаптивной тренировки, а архитектура при этом останется достаточно простой для дальнейшего развития.
